# フィードのマージ（`mergeFeeds`）

取得したフィードを一覧へマージする処理。タイムライン・カスタムフィード・リスト・スターターパック・プロフィールで共通（#107）。

## 「ポスト」と「フィードの項目」

フィードの項目は、ポストと `reason` の組。同じポストが通常の項目と複数のリポストとして返ることがあるので、用途で同一性を使い分ける。

| 用途 | 同一性 | 理由 |
|---|---|---|
| 一覧の重複除去 | `post.uri` | 組で分けると、同じポストが複数並ぶ |
| 欠落の判定 | `post.uri` と `reason` の組 | 既存ポストのリポストは新しい項目で、一覧とつながっている根拠にならない |

- リポストの組は `reason.by.did` と `reason.indexedAt` で比べる。`reason.uri` はレキシコンで省略可能なので使わない
- `reasonPin` は `reason` なしと同じに扱う。ピン留めはプロフィールで別途表示しており、それ以外ではただのポストとして扱う

## 欠落の判定

取得分が一覧とつながっていない時だけ、欠落ボタン（`__cursor`）を付ける。

1. 一覧の最古が取得分にあれば、つながっている
2. なければ、取得分の最古から順に見る
   - 一覧にないポストなら、欠落あり
   - 組が一致すれば、つながっている
   - 同じポストで `reason` だけ違えば、次に新しい項目へ進む
   - 最後まで判定できなければ、欠落あり

判断の理由:

- **「1 件でも一致すれば、つながっている」としない**: ピン留めや再登場は時系列と関係ない位置に返るので、取得がどこまで届いたかの根拠にならない
- **一覧の最古を先に確認する**: 一覧が取得件数に近いと、取得分の最古が一覧の末尾を越える。確認しないと、つながっているのにボタンが出て、押すたびに古いポストが一覧の途中に入り、フィードの終わりまで続く
- **重複を除く前の取得分で判定する**: 除いた後だと、一覧と一致する項目が捨てられていることがある
- **見逃しより余分なボタンを許容する**: 欠落は気づけないが、余分なボタンは押せば分かる

## 欠落ボタンの付け先

- 実際に追加した項目の最古に付ける。取得分の最古は重複除去で一覧に入らないことがある
- 抜け漏れ取得で 1 件も追加されなければ、元の項目に新しいカーソルを付け直す。同じカーソルが返った時は取得が進まないので、付け直さない

## 既存項目の更新

新着取得の時だけ、項目のオブジェクトを残し、`post`・`reply`・`feedContext`・`reqId` を新しいデータに置き換える。

- **過去取得と抜け漏れ取得では更新しない**: 画面より上の項目の高さが変わると、スクロール位置がずれる。高さが変わる原因（リポストミュートのマスク、ラベル、引用先の切り離しなど）を個別に塞ぐより、更新しない方が確実。再び届いた項目のいいね数などは、次の新着取得まで古いままになる
- **丸ごと置き換えない**: 以前は置き換えてから注入プロパティを書き戻しており、書き戻し漏れで値が失われる原因になっていた
- **`__custom` は引き継ぐ**: 翻訳やマスク解除などの表示の状態を保つ。`opThreadPostIndex` / `opThreadPostCount` だけは API 由来なので新しい値を使う
- **`reason` は残す**: 取得の経路で変わるので、更新すると表示が揺れる。例外はリポストミュートの差し替え（[repost-mute.md](repost-mute.md)）
- **`updatePostProps` は使わない**: `cid` や `viewer.replyDisabled` などを更新しないので、通常のポストでこれらが更新されなくなる。この関数の更新漏れは #112 で調査する

## 残る制限

修正しないと決めたもの:

- アルゴリズム系のフィードで、再登場したポストが取得分の最古に来るか、一覧の最古のポストが再登場すると欠落を見逃す。時系列でないフィードでは原理的に防げない
- 新着取得で 1 件も追加されなければ、ボタンの付け先がないので欠落を検知できない。取得分の全件が既存ポストのリポストの時だけ起きる

余分なボタンが出る場合:

- アルゴリズム系のフィードでは、取得分の最古が一覧にないことが多い
- 一覧の最古のポストが削除された状態で取得分が末尾を越えると、上記の連鎖が起きる
- 抜け漏れ取得の取得分が次の欠落を越えると、越えた位置にも出る。押せば解消する

未対応:

- #110 フォロー中フィードの新着判定も `post.uri` だけで比較している。一覧との比較のまま組の判定に変えると、既存ポストのリポストは一覧に追加されないので、取得してもフラグが点き直す
- #111 取得分が一覧の末尾や次の欠落を越えると、古いポストが一覧の先頭や途中に入る

## 変更時の確認

- `merge-feeds.ts` は Vue と `inherit-quote-custom` にしか依存しないので、esbuild でバンドルすれば架空データを Node で試せる。リポジトリの外のスクリプトから使う時は `NODE_PATH` が必要

  ```sh
  NODE_PATH=$PWD/node_modules npx esbuild <スクリプト> --bundle --platform=node --format=cjs --alias:@=./src --outfile=<出力先>
  ```

- 時系列のフィードを模したシミュレーションでは、ボタンをすべて押した後に欠落が残らないことを確かめる
- 過去取得と抜け漏れ取得の前後で、既存項目の `post` と `reason` が同じオブジェクトのままであることを確かめる
- 実機では、欠落が自然には再現しにくいので、取得件数（`consts.json` の `LIMIT_OF_FETCH_*`）を一時的に減らして試す
