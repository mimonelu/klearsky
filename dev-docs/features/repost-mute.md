# リポストミュート・引用リポストミュート

特定ユーザーのリポスト・引用リポストを折り畳む Klearsky 独自の機能。通常のミュートとは独立しており、併用できる。

## 保存先

| 種類 | レコード | 内容 |
|---|---|---|
| リポストミュート | `net.mimonelu.klearsky.repostMutes/self` | 対象ユーザーの DID と登録日時の配列 |
| 引用リポストミュート | `net.mimonelu.klearsky.quoteMutes/self` | 同上 |

- 起動時に取得して `state.repostMutes` / `state.quoteMutes` に格納し、セッションキャッシュにも保存する
- コレクション名は既存ユーザーのデータに影響するため変更しない

## 公式 API を使わない理由

公式にも範囲指定ミュート（`app.bsky.graph.muteActor` の `onlyReposts` / `onlyQuoteposts`）があるが、以下の理由で独自実装を継続している（#100）。

| | 独自実装 | 公式 API |
|---|---|---|
| 一覧 | 出せる | 出せない（`getMutes` は範囲指定ミュートを返さない） |
| 効く画面 | マスク判定を行う全画面 | `getTimeline` / `getFeed` / `getListFeed` のみ（サーバー側で除外） |
| 既存データ | そのまま使える | 移行処理が必要 |
| 他クライアント | 効かない | 効く |
| 公開範囲 | 公開（PDS のレコード） | 非公開 |

- ミュートは気軽に使われる機能であり、公開されても問題になりにくいと判断した
- 公式 API は範囲指定ミュートと通常ミュートを同時に持てない（呼ぶたびに範囲が置き換わり、範囲指定中は `viewer.muted` が false になる）。採用する場合は UI の排他制御が必要になる

## 判定（`Post.vue`）

- リポストミュート: `__custom.reason` がリポストで、リポストしたユーザーが対象
- 引用リポストミュート: 投稿者が対象で、かつ `Util.isQuotePost` が真
  - 埋め込みレコードの URI がポスト（`app.bsky.feed.post`）の場合のみ引用リポストとみなす。フィード・リスト等の埋め込みは対象外（AppView の判定に合わせている）
- 非表示にはせずマスクで折り畳む。マスクしない位置（`preview` / `slim`）では判定しない

## 一覧（`MutingUsersPopup`）

- 「個別ミュート中のユーザー」ポップアップの「リポスト」「引用リポスト」タブで表示する
- DID の配列から `getProfiles` でプロフィールを取得する。`getProfiles` は 1 リクエストあたりの件数に上限（25）があるため分割して取得する
- 独自機能であることをタブ内に明示している（他クライアントでは効かないため）
