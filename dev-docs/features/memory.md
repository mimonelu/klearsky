# メモリ使用量の計測（#101）

メモリ削減の効果は、DevTools のヒープスナップショットの比較で確かめる。画面外のポストを描画しない方向（`content-visibility`・仮想スクロール）は #55 で扱う。

## 計測手順

1. `npx vite build --minify false && npm run preview` で起動する
2. シークレットウィンドウで `http://127.0.0.1:4173/` を開き、ログインする
3. ホームタイムラインを表示し、Memory パネルでヒープスナップショットを取る
4. 計測したい操作（過去のフィードを 5 回読み込む、ホームとプロフィールを 10 回往復する等）を行い、再度スナップショットを取る
5. 2 枚目を「比較」表示にし、「サイズの差分」で並べ替える

## 注意点

- 開発サーバーでは計測しない。モジュールのソースとソースマップが文字列として載り、コード分がヒープの大半を占めてデータの増減が埋もれる
- `--minify false` でビルドする。圧縮するとクラス名が短縮され、`Link` や `PenState` が判別できない
- シークレットウィンドウで計測する。Vue Devtools 等の拡張機能がコンポーネントへの参照を保持して数値が狂う
- preview のポートでも OAuth でログインできる（ローカル開発時は `redirect_uri` を `location.port` から組み立てるため）
- スナップショットの取得時に GC が走るため、事前の GC は不要
- 読み込まれるポストは計測ごとに異なるため、1〜2% 程度の差はブレとみなす
- `(compiled code)` の増加は JIT によるもので、リークではない

## 結果の読み方

- 往復の前後で VNode やコンポーネントインスタンス（`{uid, vnode, type, …}`）の「# デルタ」が 0 なら、往復によるリークはない
- 読み込みの前後で増える分は、ポスト 1 件あたりのコストに比例する。`blink::*` はレイアウト・描画、VNode 等は Vue、`<div>` / `Text` は DOM、`(array)` / `(string)` はデータ

正体がわかりにくいコンストラクター:

| コンストラクター | 正体 |
|---|---|
| `Link` / `Dep` | Vue のリアクティブの依存追跡。描画中に参照したリアクティブなプロパティごとに作られる |
| `PenState` | hls.js の CEA-608 字幕パーサー。セグメントを読み込んだ動画 1 本につき 18,180 個 |
| `blink::GridSizingTrackCollection` | `display: grid` の要素ごとのレイアウトデータ |
