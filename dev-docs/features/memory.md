# メモリ使用量の計測（#101）

メモリ削減の効果は、DevTools のヒープスナップショットの比較で確かめる。画面外のポストを描画しない方向（`content-visibility`・仮想スクロール）は #55 で扱う。

## 計測手順

1. `npx vite build --minify false && npm run preview` で起動する
2. シークレットウィンドウで `http://127.0.0.1:4173/` を開き、ログインする
3. ホームタイムラインを表示し、Memory パネルでヒープスナップショットを取る
4. 計測したい操作（過去のフィードを 5 回読み込む、ホームとプロフィールを 10 回往復する等）を行い、再度スナップショットを取る
5. 2 枚目を「比較」表示にし、「サイズの差分」で並べ替える

## 注意点

- 開発サーバーでは計測しない。モジュールのソースとソースマップが文字列として載り、コード分がヒープの大半を占めてデータの増減が埋もれる
- `--minify false` でビルドする。圧縮するとクラス名が短縮され、`Link` や `PenState` が判別できない
- シークレットウィンドウで計測する。Vue Devtools 等の拡張機能がコンポーネントへの参照を保持して数値が狂う
- preview のポートでも OAuth でログインできる（ローカル開発時は `redirect_uri` を `location.port` から組み立てるため）
- スナップショットの取得時に GC が走るため、事前の GC は不要
- 読み込まれるポストは計測ごとに異なるため、1〜2% 程度の差はブレとみなす
- `(compiled code)` の増加は JIT によるもので、リークではない

## 画像のメモリ

デコード後の画像はヒープスナップショットに含まれない。Chrome のタスクマネージャー（列の見出しを右クリックして「画像キャッシュ」を追加）で、同じ操作の後の値を比べる。タブの「メモリ使用量」には画像キャッシュが反映されないことがある。

- アバターは公式 CDN の縮小版（`avatar_thumbnail`）を使う（`AvatarThumbnail.vue`）。原寸を使うと、過去のフィードを 5 回読み込んだ時点で画像キャッシュが約 1.8 倍になった
- `fetchBlobUrl` が返す Blob URL は、解放するまで Blob がページに残り続ける。呼び出し側で破棄時に解放し、取得中に破棄された場合は取得後すぐに解放する。

## 結果の読み方

- 往復の前後で VNode やコンポーネントインスタンス（`{uid, vnode, type, …}`）の「# デルタ」が 0 なら、往復によるリークはない
- 読み込みの前後で増える分は、ポスト 1 件あたりのコストに比例する。`blink::*` はレイアウト・描画、VNode 等は Vue、`<div>` / `Text` は DOM、`(array)` / `(string)` はデータ

正体がわかりにくいコンストラクター:

| コンストラクター | 正体 |
|---|---|
| `Link` / `Dep` | Vue のリアクティブの依存追跡。描画中に参照したリアクティブなプロパティごとに作られる |
| `PenState` | hls.js の CEA-608 字幕パーサー。セグメントを読み込んだ動画 1 本につき 18,180 個。`enableCEA708Captions: false` で生成しないようにしているため、出たら設定が効いていない |
| `blink::GridSizingTrackCollection` | `display: grid` の要素ごとのレイアウトデータ。行と列で 1 個ずつ作られ、`blink::LayoutGrid` と合わせてグリッド 1 個あたり約 4 KB |
| `blink::PaintLayerScrollableArea` | `overflow: hidden` / `auto` 等のスクロールコンテナごとに作られる。`overflow: clip` では作られない |
| `blink::PaintLayer` / `blink::ClipPaintPropertyNode` | 描画レイヤーと切り取り。`overflow` が `visible` 以外（`clip` を含む）の要素や `position` 指定の要素等に作られる |

## `content-visibility` を見送った理由（#55）

`.feed` に `content-visibility: auto` を指定して計測し、採用を見送った。

- 過去のフィードを 5 回読み込んだ直後のヒープは、約 97 MB → 約 96 MB で誤差の範囲だった。レイアウト関連の `blink::*` は 1 割強しか減らず、一度描画したポストのレイアウトは画面外に出ても大部分が残る
- ポストスレッドから戻った直後だけ、ヒープが約 96 MB → 約 67 MB、画像キャッシュが 51 MB → 23 MB に減った。ポストが作り直され、画面外のポストが描画されないためで、読み進めれば再び積み上がる
- 戻った時のスクロール位置がずれる

画面外のポストを描画しない方向の効果を測る時は、戻った直後の値だけで判断せず、順にスクロールして読み進めた直後の値も比べる。
